# 카드 페이지 넘김 — 설계

2026-09-06 · 시안: `docs/prototypes/2026-09-06-card-paging.html`

## 무엇을 바꾸나

카드의 `<details>` 아래로-펼침을 없애고, 카드를 **좌우로 넘기는 4쪽 무한 페이저**로 바꾼다.
지금 펼치면 나오는 내용이 그대로 다음 쪽이 된다. 카드 크기는 변하지 않는다.

## 왜

데스크탑 다열 격자(2026-09-06, `DESIGN.md`)에서 카드를 펼치면 **그 행의 나머지 칸이 최대
700px 빈다.** `align-items:start`라 카드 자체는 안 늘어나지만 행 높이가 펼친 카드를 따라간다.
masonry는 미출시, CSS `columns`는 정렬 순서가 세로로 흘러 "하락 큰 순"이 깨져 읽힌다.

페이저는 이 문제를 **0으로** 만든다 — 카드 높이가 애초에 변하지 않기 때문이다.

모바일에도 같이 적용한다. 단일 컬럼엔 700px 구멍 문제가 없지만, 지금도 카드를 펼치면 700px이
자라 스크롤 위치를 잃고 다음 카드가 화면 밖으로 밀린다. 그리고 같은 카드가 폭에 따라 열림
모델이 다르면 혼란이다 — 같아 보이는 건 같게 동작해야 한다.

## 쪽 구성 (4쪽)

| 쪽 | 내용 | 최장(실측) |
|---|---|---|
| 0 표지 | 도판 · 이름 · 가격 · 제철 띠 · 한마디 (지금 접힘 상태 그대로) | **346px** |
| 1 시세·영양 | 스파크라인 + 영양 6칸 | 293px |
| 2 고르는 법 | `howToPick` | 192px |
| 3 보관·쓰임 | `howToStore` · `howToUse` + 레시피 진입 칩 | 343px |

**고정 높이 = 가장 긴 쪽 = 표지(346px).** 표지가 최장이어야 기본 화면에 여백이 안 생긴다.

### 이 분할은 미감이 아니라 산술로 골랐다

`produce.json` 84개 · `recipes.json` 75개 실측. 후보와 여백:

| 안 | 쪽수 | 고정높이 | 표지 여백 | 속쪽 여백 평균 |
|---|---|---|---|---|
| 다 쪼갬 | 6 | 346 | 0 | 158px |
| 시세·영양 합침 | 5 | 346 | 0 | 125px |
| **채택** | **4** | **346** | **0** | **70px** |
| 손질 통째 | 4 | 396 | **50px** | 127px |

- **손질을 통째로 두면 안 된다.** 84개 중 **39개(46%)**가 표지보다 길어져 고정 높이를 396px로
  밀어올리고 표지 아래가 상시로 빈다(최장 복숭아 396px). 갈라야 한다. 의미로도 맞다 —
  고를 때(가게)와 집에 온 뒤는 때가 다르다.
- **레시피 조리 단계는 쪽에 못 넣는다.** 75개 중 **73개**가 346px 초과, 최장 872px, 중앙값
  490px. 순서라 쪼갤 수도 없다. **지금의 카드 위 핀 메모 오버레이(`RecipeMemo`·`.memoLayer`)를
  그대로 둔다** — 그게 우연이 아니라 길어서 그렇게 된 것이었다. 쪽에는 진입 칩만 들어간다.
  (설계 초기에 "레시피가 쪽으로 흡수돼 오버레이 코드가 준다"고 봤던 것은 **틀렸다.**)
- 남는 대가: **`고르는 법` 쪽이 154px 빈다.** 네 안 중 가장 작지만 0은 아니다.

## Full bleed — 가로 여백은 카드가 아니라 쪽이 갖는다

지금 카드는 `padding: var(--slg)`로 사방 16px을 쥐고 있다. 그대로 두면 쪽이 **16px 안쪽 창
안에서** 미끄러져 "액자 속 슬라이드"가 된다 — 낱장을 넘기는 게 아니라 창 안의 내용이 갈리는
것처럼 읽힌다.

가로 패딩을 카드에서 쪽으로 옮긴다:

- `.card { padding: var(--slg) 0 }` — 세로 여백은 카드에 남는다(쪽마다 위아래가 어긋나면 안 된다)
- `.page { padding: 0 var(--slg) }`
- 뷰포트가 카드 테두리까지 넓어져(실측: 카드 233px / 뷰포트 230px, 남은 건 테두리 1px씩)
  들어오는 쪽이 카드 가장자리에서 나오고, 나가는 쪽은 가장자리에서 잘린다
- 내용 폭은 그대로다(쪽이 같은 여백을 쥐므로) — 고정 높이 346px도 변하지 않는다

**예외는 도트 줄뿐이다.** 뷰포트 밖이라 자기 여백을 갖는다: 구분 점선은 카드 폭 전체를 긋고
(낱장의 밑단), 도트는 쪽과 같은 눈금으로 들여 내용과 같은 기둥에 선다.

## 속쪽 머리

속쪽마다 `[작은 도판 40px | 품목명 | 쪽 라벨]` 한 줄. 4열 격자에서 여러 장을 각기 다른 쪽에
넘겨두면 "시세"만 있고 무슨 품목인지 알 수 없다. 표지가 최장이라 속쪽엔 어차피 여백이
남으므로, 그 여백의 일부를 신원에 쓴다.

## 무한 루프 — 클론을 만들지 않는다

트랙 위치는 가상 인덱스 `v`로 무한히 흐르고(…−1, 0, 1, 2…), 각 쪽은 자기 자리에서
`translateX(k · N · W)`만큼 건너뛰어 `v` 근처에 다시 나타난다(`k = round((v − i) / N)`).
0쪽에서 왼쪽으로 당기면 마지막 쪽이 **실제로** 왼편에 서 있어 손가락을 따라오는 내내 이어진다.

DOM은 N장 그대로다 — 클론 방식과 달리 React에서 같은 컴포넌트를 두 벌 렌더하지 않는다.
도트의 현재 위치는 `((v % N) + N) % N`.

## 제스처

`apple-design` 렌즈. **바닐라로 충분하다 — Motion 등 라이브러리를 들이지 않는다**(앱의
경량·무추적 원칙). 프로토타입에서 60줄로 전부 확인했다.

- **1:1 추적** — Pointer Events + `setPointerCapture`(포인터가 카드를 벗어나도 계속 따라온다)
- **축 판별** — 10px 히스테리시스. 세로면 페이지 스크롤에 양보하고 제스처를 포기한다
  (`touch-action: pan-y`)
- **중단 가능** — `pointerdown`에서 날던 애니메이션을 현재 위치에 그대로 붙잡는다
  (presentation value에서 재개; 목표 값에서 시작하면 튄다)
- **속도 인계** — 마지막 6개 `pointermove`로 px/s를 재어 스프링 초기 속도로 넘긴다
- **모멘텀 투영** — `landing = x + (v/1000)·0.998/(1−0.998)`
- **한 제스처 = 한 쪽** — 투영 결과를 `vStart ± 1`로 자른다. 세게 던지면 3쪽을 건너뛰어
  4쪽 루프에서 방향을 잃는다(iOS 페이징 스크롤과 같은 처리)
- **러버밴딩 없음** — 경계가 없다
- 스프링: `K=300, C=30` (ζ≈0.87, response≈0.35s), `requestAnimationFrame`
- **`transform`·`opacity`만** 애니메이트

## 접근성 · 무JS

`<details>`가 공짜로 주던 것을 직접 만들어야 한다.

- **무JS 폴백**: 프리렌더 산출물은 지금의 `<details>` 그대로 낸다. 하이드레이션 후에만 페이저로
  승격한다 — `App.tsx`의 `ready` state가 이미 쓰는 패턴이고(카테고리 세그먼트가 "하이드레이션
  후 JS radiogroup"), 새로 발명할 게 없다. JS가 없으면 지금과 똑같이 동작한다.
- 쪽은 `role="tabpanel"`, 도트는 `role="tab"`. **←/→ 방향키**로 넘긴다 (`ButtonGroup`에 선례)
- `:focus-visible` 쪽빛 2px (전역 규칙 그대로)
- `prefers-reduced-motion: reduce`면 스프링을 끄고 **즉시 전환**한다

## 디자인 규율

- 표지를 벗어나 있으면 카드 테두리가 계절색으로 물든다 — 지금 `.card[open]`이 주던 신호를
  그대로 잇는다
- 도트는 카드 하단, 점선 구분선 아래. 쪽빛만(웜 컬러는 글자·마커에 안 쓴다)
- 마스킹테이프·기울기·부양은 그대로

## 경계 (`CLAUDE.md` 스타일 경계)

- **순수 로직 없음** — `picks`/`card`/`app`은 손대지 않는다. `CardView`도 그대로다.
  쪽 나눔은 표시 결정이라 `components/`에 산다.
- **제스처 훅** `src/components/usePager.ts` — Pointer Events + 스프링. 표시 로직 없음.
- **`ProduceCard.tsx`** — `<details>` → 페이저 마크업. `ready`면 페이저, 아니면 `<details>`.
- **`ProduceCard.module.css`** — 트랙·쪽·고정 높이·도트(스케일 밖 기하라 모듈이 맡는다)
- `RecipeMemo`·`.memoLayer`는 그대로 둔다
